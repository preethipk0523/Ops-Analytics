# Operations Performance Analytics (SQL + Python + Dashboard)

An end-to-end data analyst project: take a messy export of operations tickets, clean it,
load it into a SQL database, calculate service KPIs with SQL, and show them in a dashboard.

> **Important:** the data is **simulated** (generated by `src/generate_data.py`). It is not real
> company data. Be explicit about this if you mention the project in a CV, README or interview.

## What business question does it answer?
An operations manager wants to know: *Are we resolving tickets fast enough? Which teams or
priorities miss their SLA? Is the backlog growing? Where should we act first?*

| KPI | Definition |
|---|---|
| Resolution time | `resolved_at - created_at`, in hours |
| SLA target | Critical 4 h, High 8 h, Medium 24 h, Low 72 h |
| SLA adherence | % of resolved tickets finished within their SLA target |
| Backlog | Tickets created so far minus tickets resolved so far |
| Workload | Tickets handled per agent, compared with the average |

## Pipeline

```
generate_data.py  ->  clean_data.py  ->  load_db.py  ->  run_kpis.py  ->  dashboard / Power BI
 raw_tickets.csv     tickets_clean.csv   ops.db (SQLite)   outputs/kpis/*.csv
                     + quality report
```

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

make all            # or run the 4 commands below one by one
python -m src.generate_data
python -m src.clean_data
python -m src.load_db
python -m src.run_kpis

python -m pytest -q             # unit tests
streamlit run dashboard/app.py  # interactive dashboard
```

## Project structure

```
src/generate_data.py   simulated raw data with deliberate quality problems
src/clean_data.py      cleaning rules + data-quality report
src/load_db.py         load into SQLite using sql/schema.sql
src/run_kpis.py        run sql/kpi_queries.sql, save one CSV per KPI
sql/                   schema and the 8 KPI queries (CTEs, window functions)
dashboard/app.py       Streamlit dashboard
tests/                 pytest tests for cleaning and SQL
docs/learning_guide.md how every piece works + exercises + interview questions
docs/powerbi_guide.md  build the same dashboard in Power BI (DAX measures included)
.github/workflows/     CI: runs tests and the full pipeline on every push
```

## Data quality problems injected (and fixed)
Duplicate rows, inconsistent team names (`support`, `SUPPORT`, ` Support `), missing priority,
`N/A` text in a date column, and resolved dates earlier than created dates.
See `outputs/data_quality_report.md` after running the pipeline.

## Skills practised
SQL (CTEs, window functions: `RANK`, `NTILE`, running `SUM`, moving `AVG`), Python (pandas),
data cleaning and validation, KPI definition, unit testing (pytest), CI (GitHub Actions),
dashboarding (Streamlit / Power BI).

## Before you put this on a CV
Run it, read `docs/learning_guide.md`, change something (a new KPI, a new cleaning rule, your
own dataset), and make sure you can explain every file. Describe it honestly as a personal
project using simulated data.
